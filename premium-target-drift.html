Why it drifts, and what to anchor to instead

  • DOM selectors: a selector built from the current render (an id like #premium-541, or XPath text() matching the literal string) is really a snapshot, not a target. Anchor to something that doesn't change with the value — a data-testid, an aria-label, or a fixed position relative to the static label ("the sibling of the node whose text is Total Premium").
  • NLP / AI-based locators: the same failure shows up one level up — if the tool resolves "the element that says Total Premium – $541" by matching that exact phrase, re-anchor the instruction to the constant part ("the value next to the Total Premium label") and let it read the number rather than match it.
  • On-screen / coordinate targeting: a captured bounding box is stable only as long as layout doesn't reflow around the new value's length. Prefer targeting relative to the fixed label or container, not an absolute region baked in at capture time.
  • Visual validation: for full-page or region checks, an exact match level will flag every premium change as a diff. A regex-based content check, an accessibility-region check, or a deliberately ignored/floating region over just the value keeps the surrounding layout under strict validation while treating the number itself as expected-to-change.
